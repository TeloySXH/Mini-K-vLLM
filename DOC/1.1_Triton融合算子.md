# 1.1 Triton 融合算子 🚀

> 基于 `KvChat/layers/attention.py`、`KvChat/layers/compress_utils.py`、`KvChat/engine/model_runner.py` 与 `Test/test_prefill.py` 的源码事实撰写。

## 📌 总览

Mini-S 在推理热点路径上**全面采用 Triton 自研算子**，覆盖三大核心场景：

| 🎯 场景 | 🔧 算子 | 📍 文件位置 | ⚡ 关键能力 |
| --- | --- | --- | --- |
| Prefill 注意力 | `flash_attention_varlen_kernel` | `KvChat/layers/attention.py` | 变长序列 + Online Softmax + GQA |
| Decode 注意力 | `paged_attention_decode_kernel` | `KvChat/layers/attention.py` | Paged KV + 在线 softmax + GQA |
| KV Cache 写入 | `store_kvcache_kernel` | `KvChat/layers/attention.py` | slot_mapping 直写分页缓存 |
| KV 压缩取数 | `_gather_kv_chunk_kernel` | `KvChat/layers/compress_utils.py` | 分块 chunk gather |
| KV 压缩搬运 | `_gather_kv_rows_kernel` / `_scatter_kv_rows_kernel` | `KvChat/layers/compress_utils.py` | 行级 load / store |
| 融合写入（含 GQA Query 聚合） | `store_qkvcache_kernel` | `KvChat/layers/compress_utils.py` | KV 写入 + Q 头分组平均 |

> 📦 设计哲学：**「分页存储 + 在线 softmax + 变长批处理 + 启动期预编译」**，最大化共享内存利用率，最小化 kernel launch 开销。

## 一、🗂️ Store KV Cache：`store_kvcache_kernel`

### 1.1 功能定位
将一批 token 的 K / V 张量按 `slot_mapping` 写入**分页 KV Cache**。这是 prefill 每个 token 都会触发的高频算子。

### 1.2 张量布局

```
Input  key/value : (num_tokens, num_kv_heads, head_dim)
Cache  k_cache/v_cache : (num_blocks, block_size, num_kv_heads, head_dim)
slot_mapping : (num_tokens,)  —— 每个 token 对应的物理 slot；-1 表示跳过
```

### 1.3 Grid 设计

```python
grid = (num_tokens, num_kv_heads)
```

- ✅ **每个 program 处理「一个 token × 一个 KV head」**
- ✅ 利用 `tl.program_id(0/1)` 双轴并行，避免循环

### 1.4 核心逻辑（精简）

```16:52:KvChat/layers/attention.py
    token_idx = tl.program_id(0)
    slot_idx = tl.load(slot_mapping_ptr + token_idx)
    if slot_idx == -1:
        return

    block_idx = slot_idx // block_size
    block_offset = slot_idx % block_size
    head_idx = tl.program_id(1)
    ...
    key = tl.load(key_ptr + input_offset)
    value = tl.load(value_ptr + input_offset)
    tl.store(k_cache_ptr + cache_offset, key)
    tl.store(v_cache_ptr + cache_offset, value)
```

🌟 **亮点**
- 通过 `slot_idx == -1` 直接 early-return，天然支持 padding token 跳过。
- `head_offsets = tl.arange(0, head_dim)` 让单个 head 一次性向量化加载，命中 LDST 合并访问。

## 二、⚡ Flash Attention Prefill：`flash_attention_varlen_kernel`

### 2.1 算法本质：Online Softmax (O(N) 内存)
相比 PyTorch 的 O(N²) 标准实现（见 `Test/test_prefill.py` 的 `pytorch_standard_attention`）和 Naive Triton 实现（必须把整个注意力矩阵塞进共享内存），Flash 版本通过**在线 softmax 递推 (`m_i, l_i, acc`)** 把内存压到 O(N)。

### 2.2 Grid 设计：三维并行 🎲

```python
grid = (triton.cdiv(max_seq_len, BLOCK_M), num_heads, num_seqs)
```

| 轴 | 含义 |
| --- | --- |
| `program_id(0)` | Query 块 (`start_m`) |
| `program_id(1)` | Query 头 (`off_h`) |
| `program_id(2)` | 序列下标 (`seq_idx`) |

✅ **变长序列友好**：通过 `cu_seqlens_q_ptr` 加载本序列的 `[seq_start, seq_end)`，每个 program 只负责本序列 ✂️。

✅ **GQA 支持**：通过 `kv_head_idx = off_h // (num_heads // num_kv_heads)` 把 Query head 映射到 KV head。

### 2.3 Online Softmax 核心循环 🔁

```140:172:KvChat/layers/attention.py
    num_blocks = tl.cdiv(seq_len, BLOCK_N)

    for block_n in range(num_blocks):
        ...
        qk = tl.dot(q, k)
        qk = qk * scale
        mask_causal = (offs_m[:, None] + seq_start) >= (offs_n[None, :] + seq_start)
        qk = tl.where(mask_causal & mask_n[None, :], qk, -1e10)

        m_ij = tl.max(qk, axis=1)
        m_i_new = tl.maximum(m_i, m_ij)
        alpha = tl.exp(m_i - m_i_new)
        p = tl.exp(qk - m_i_new[:, None])

        acc = acc * alpha[:, None]
        ...
        acc = acc + tl.dot(p.to(v.dtype), v)
        l_i = l_i * alpha + tl.sum(p, axis=1)
        m_i = m_i_new
```

📝 **逐步解释**
1. **`m_ij`**：当前 KV 块内的最大 logit。
2. **`m_i_new`**：跨块累计最大值，保证数值稳定。
3. **`alpha`**：把已累加的 `acc` 与 `l_i` 重新缩放到新 max。
4. **`p`**：当前块的 softmax 数值（未归一化）。
5. 最终 `acc / l_i[:, None]` 得到归一化输出。

### 2.4 Tile 自适应 🪄

> 💡 注释明确写道：**「SM occupancy 从 ~10% 提升到 40-50%，预计吞吐 +10-15%」**，这是基于 96KB 共享内存上限做的实测调优。

### 2.5 与 Naive Triton 的对比 📊

`Test/test_prefill.py` 内置了三方对比：

| 实现 | 内存复杂度 | 共享内存约束 | 适用 seq_len |
| --- | --- | --- | --- |
| `pytorch_standard_attention` | O(N²) | 无（HBM）| 任意 |
| `naive_triton_attention_kernel` | O(N²) | `BLOCK_SIZE² * 4B < 48KB` | ≤ 64（head_dim>64）/ ≤128 |
| **`flash_attention_varlen_kernel`** ✅ | **O(N)** | 仅 `O(BLOCK_M × head_dim)` | 任意（推理实际可达 4096+） |

> ⚠️ Naive 版有显式 `if seq_len > BLOCK_SIZE: return` 的限制，Flash 版用 `mask_m = offs_m < seq_len` 在 kernel 内部全程 mask 化处理，**移除了 return 语句**（更友好的 Triton IR）。

## 三、🧱 Paged Attention Decode：`paged_attention_decode_kernel`

### 3.1 为什么 decode 不能复用 Prefill kernel？

- Decode 阶段 q 只有 1 个 token，但 KV 来自**分页存储**（block_tables 间接寻址）。
- 必须根据 `context_lens` 动态裁剪有效 token 范围。

### 3.2 Grid 设计

```python
grid = (batch_size, num_heads)
```

每个 program 处理 **「一个 batch × 一个 head」** 的单 query 向量。

### 3.3 Block Table 间接寻址 🪜

```308:317:KvChat/layers/attention.py
            block_num = token_idx // block_size
            block_offset = token_idx % block_size

            valid_block = (block_num < max_num_blocks) & (token_idx < context_len)

            block_table_offset = batch_idx * max_num_blocks + block_num
            physical_block_idx = tl.load(block_tables_ptr + block_table_offset)

            block_exists = physical_block_idx != -1
```

🔑 **关键点**：通过 `block_tables` 把逻辑 token 索引翻译成**物理 block id**，再 + `block_offset` 拿到真实 cache slot。这就是 **vLLM PagedAttention 思想的 Triton 复刻**。

### 3.4 双重 mask（长度 + 因果） 🎭

```296:299:KvChat/layers/attention.py
        query_pos = context_len - 1
        mask_causal = offs_n <= query_pos
```

✅ 用 `tl.where(mask_i & valid_block & block_exists, ..., -1e10)` 替代分支跳转，规避 Triton 早期版本对 `break/continue` 的限制。

### 3.5 Tile 选择

```422:423:KvChat/layers/attention.py
    BLOCK_N = 128 if head_dim <= 128 else 64
```

> 注释：**「decode kernel BLOCK_N 增大，预计提速 15-25%」**。

## 五、🗜️ KV 压缩链路上的 Triton 算子

KV Cache 压缩（SnapKV 算法见 `KvChat/layers/CompressMethod.py`）会触发**「取数 → 选 top-k → 物理搬运」**三步，其中两步使用 Triton。

### 5.1 `_gather_kv_chunk_kernel`：分页 KV → 紧凑 (m, S, D) 张量 📦

```172:214:KvChat/layers/compress_utils.py
@triton.jit
def _gather_kv_chunk_kernel(
    k_flat_ptr, v_flat_ptr,
    out_k_ptr, out_v_ptr,
    block_tables_ptr,
    max_blocks: tl.constexpr,
    block_size: tl.constexpr,
    S: tl.constexpr,
    D_kv: tl.constexpr,
    chunk_size: tl.constexpr,
):
    seq_i = tl.program_id(0)
    chunk_i = tl.program_id(1)
    ...
    block_id = tl.load(block_tables_ptr + block_addr, mask=load_block_mask, other=-1)
    slot = block_id * block_size + offset_in_block
    valid_slot = (block_id >= 0) & load_block_mask
    ...
    k_rows = tl.load(k_flat_ptr + base_addr_kv[:, None] + offs_kv, mask=valid_slot[:, None], other=0.0)
    v_rows = tl.load(v_flat_ptr + base_addr_kv[:, None] + offs_kv, mask=valid_slot[:, None], other=0.0)
    ...
    tl.store(out_k_ptr + out_base_addr[:, None] + offs_kv, k_rows)
    tl.store(out_v_ptr + out_base_addr[:, None] + offs_kv, v_rows)
```

**Grid**：`(m, num_chunks)`，其中 `m = 待压缩序列数`，`num_chunks = ceil(S / chunk_size)`。

🌟 **设计要点**
- 把 `(num_blocks * block_size, D_kv)` 的二维 flatten 视图作为输入，简化指针算术。
- `chunk_size`（默认 128）+ `D_kv` 一次性加载一整个 (chunk × head_dim×heads) 块，**实现矩阵化 gather**。
- 输出布局直接对接 SnapKV 期望的 `(m, num_kv_heads, S, head_dim)`（在 host 端通过 `permute(0, 2, 1, 3)` 完成）。

### 5.2 `_gather_kv_rows_kernel` & `_scatter_kv_rows_kernel`：两阶段安全搬运 🔄

```252:303:KvChat/layers/compress_utils.py
@triton.jit
def _gather_kv_rows_kernel(...):
    pid = tl.program_id(0)   # each program handles one source row
    src = tl.load(src_idx_ptr + pid)
    for d in range(0, D_k, BLOCK_D):
        ...
        k_vals = tl.load(k_ptr + src_addr, mask=mask, other=0.0)
        ...
        tl.store(temp_k_ptr + tmp_addr, k_vals, mask=mask)

@triton.jit
def _scatter_kv_rows_kernel(...):
    pid = tl.program_id(0)   # each program handles one destination row
    dst = tl.load(dst_idx_ptr + pid)
    for d in range(0, D_k, BLOCK_D):
        ...
        tl.store(k_ptr + dst_addr, k_vals, mask=mask)
```

🛡️ **为什么要两阶段？**
> 引用源码注释：*"We use a two-phase approach (load to temp, then store) to avoid overwrite hazards."*
>
> 因为压缩后的 R 个保留 token 要被搬到 KV cache 的前 R 个 slot，**源 / 目标可能重叠**，先 gather 到临时缓冲再 scatter 是 in-place 安全搬运的经典做法。

> 🧩 注：当前 `MyCompressCompact` 主路径使用了 `index_select + index_copy_` 这种 PyTorch 原语完成搬运（见 `compress_utils.py` L134-137）；上述 gather/scatter 两个 Triton kernel 是**为后续完全 Triton 化 in-place 搬运准备的备选实现**。

### 5.3 `store_qkvcache_kernel`：融合写入 + GQA Query 聚合 🎯

```306:357:KvChat/layers/compress_utils.py
@triton.jit
def store_qkvcache_kernel(
    key_ptr, value_ptr, query_ptr,
    q_cache_ptr, k_cache_ptr, v_cache_ptr,
    slot_mapping_ptr,
    D_kv: tl.constexpr,
    D_q_out: tl.constexpr,
    orig_heads: tl.constexpr,
    group_size: tl.constexpr,
    head_dim: tl.constexpr,
    stored_heads: tl.constexpr,
    q_dtype_flag: tl.constexpr,   # 0=float32,1=float16,2=bfloat16
):
    idx = tl.program_id(0)
    slot = tl.load(slot_mapping_ptr + idx)
    if slot == -1:
        return
    ...
    # 1) 直接写 K/V cache
    tl.store(k_cache_ptr + k_cache_pos, key_row)
    tl.store(v_cache_ptr + k_cache_pos, val_row)

    # 2) 把 Hq 个 query head 在 group 内做平均，落到 stored_heads 上
    base_q_in = idx * (orig_heads * head_dim)
    for oh in range(stored_heads):
        acc = tl.zeros((head_dim,), dtype=tl.float32)
        in_start = oh * group_size
        for g in range(group_size):
            in_head = in_start + g
            q_in_offsets = base_q_in + in_head * head_dim + tl.arange(0, head_dim)
            q_vals = tl.load(query_ptr + q_in_offsets)
            acc = acc + q_vals.to(tl.float32)
        acc = acc / group_size
        ...
        tl.store(q_cache_ptr + q_out_pos, acc.to(<dtype>))
```

✨ **三合一融合**
1. **K cache 写入**
2. **V cache 写入**
3. **Q 聚合**：对 GQA 中同 group 的 Query head 做 fp32 累加 → 平均 → 转回原 dtype（fp16/bf16/fp32 三态由 `q_dtype_flag` 控制），结果落到 `q_cache`。

🎁 **价值**
- 一次 grid launch 替代 3 次独立 launch + Python 端均值计算。
- fp32 累加避免 bf16 精度衰减。
- 把 query 提前压成 `stored_heads = num_kv_heads` 形状，直接对齐 SnapKV 期望的 KV head 维度，省一次 reshape。
