# 1.7 分布式支持体系 🌐

> **目标**：通过 **NCCL + Tensor Parallel + 共享内存广播** 三层设计，让 KvChat 可以在 1–8 张 GPU 之间切分一个 Qwen3 模型并保持单一调度入口。

---

## 🧱 1.7.1 整体拓扑

```
                          ┌──────────────────────────┐
            User ──▶  Rank 0 (Master)               │
                       │ ├── Scheduler              │
                       │ ├── Tokenizer              │
                       │ ├── ModelRunner (TP shard) │
                       │ └── 共享内存 nanovllm       │
                       └─┬────────────┬──────────┬──┘
            写命令到 SHM  │ NCCL all_reduce / gather │
                         ▼            ▼          ▼
                   ┌──────────┐ ┌──────────┐ ┌──────────┐
                   │  Rank 1  │ │  Rank 2  │ │  Rank N-1│
                   │ ModelRun │ │ ModelRun │ │ ModelRun │
                   └──────────┘ └──────────┘ └──────────┘
                        ↑ 监听 mp.Event + 读 SHM
```

- 仅 **Rank 0** 持有 Scheduler / Sampler / Tokenizer 的"业务大脑"。
- 其余 rank 只跑 ModelRunner 的 forward 切片，结果通过 NCCL 汇总到 Rank 0。

## 🚀 1.7.2 进程启动：`LLMEngine.__init__`

```python
# KvChat/engine/llm_engine.py
ctx = mp.get_context("spawn")
for i in range(1, config.world_size):
    event = ctx.Event()
    process = ctx.Process(target=worker_process, args=(config, i, event))
    process.start()
    self.ps.append(process); self.events.append(event)

# 主进程作为 Rank 0
self.model_runner = ModelRunner(config, 0, self.events)
```

- ✅ 使用 `spawn` 而非 fork，避免 CUDA 上下文继承导致的 NCCL 初始化失败。
- ✅ 每个 worker 拥有独立 `mp.Event`，主进程一次写 SHM、广播 set 多个 event。

worker 进入循环：

```python
def worker_process(config, rank, event):
    sys.stdout = ... line-buffering
    model_runner = ModelRunner(config, rank, event)
    if model_runner.world_size > 1 and rank > 0:
        model_runner.loop()        # 阻塞监听
```

`atexit.register(self.exit)` 确保用户 Ctrl+C 时也能正常 join 子进程。

## 🔌 1.7.3 NCCL 进程组

```python
# KvChat/engine/model_runner.py
if self.world_size > 1:
    dist.init_process_group(
        "nccl",
        "tcp://localhost:2333",     # 单机多卡，TCP 引导
        world_size=self.world_size,
        rank=rank
    )
torch.cuda.set_device(rank)
```

- 🛰️ **后端 NCCL**：GPU-GPU 直连，all_reduce / gather 速度最优。
- 🧩 **`set_device(rank)`**：保证当前 rank 的所有张量都落在自己的卡上。
- 🛑 退出时通过 `dist.destroy_process_group()` 干净销毁，并 `dist.barrier()` 确保 SHM 释放有序。

## ✂️ 1.7.4 Tensor Parallel：模型切分

### 切分策略

| 模块 | 切分方式 | 文件 |
| --- | --- | --- |
| `VocabParallelEmbedding` | 词表沿第 0 维切分 | `KvChat/layers/embed_head.py` |
| `ParallelLMHead` | 词表沿第 0 维切分，前向后 `dist.gather` 到 rank 0 | 同上 |
| `ColumnParallelLinear` | 输出维切分 (`tp_dim=0`) | `KvChat/layers/linear.py` |
| `MergedColumnParallelLinear` | 多输出 chunk 各自再按列切 | gate_up_proj |
| `QKVParallelLinear` | Q/K/V 三段分别按 head 切 | qkv_proj |
| `RowParallelLinear` | 输入维切分，前向后 `dist.all_reduce` | o_proj、down_proj |
| Attention head 数 | `num_heads / tp`、`num_kv_heads / tp` | `Qwen3Attention.__init__` 断言整除 |

### 通信规则

```python
# RowParallelLinear.forward
y = F.linear(x, self.weight, self.bias if tp_rank==0 else None)
if tp_size > 1:
    dist.all_reduce(y)        # 加和聚合各列分量
return y
```

```python
# ParallelLMHead.forward
logits = F.linear(x, self.weight)
if tp_size > 1:
    all_logits = [...]
    dist.gather(logits, all_logits, 0)
    logits = torch.cat(all_logits, -1) if tp_rank==0 else None
return logits
```

> 🎯 **bias 仅 rank 0 加**：避免 `all_reduce` 后 bias 被叠加 `tp_size` 次。

### Tensor Parallel 安全降级

```python
def get_distributed_world_size():
    try: return dist.get_world_size()
    except ValueError: return 1
```

未初始化进程组时（如 `tensor_parallel_size=1` 调试模式），`world_size` 自动退化为 1，整套并行代码无需分支即可运行单卡。

## 📨 1.7.5 主从通信：共享内存 + Event

`ModelRunner` 在 rank 0 创建一段 16MB 共享内存：

```python
self.shm = SharedMemory(name="nanovllm", create=True, size=2**24)
dist.barrier()
```

调用流程 `call()`：

```python
def call(self, method_name, *args):
    if world_size > 1 and rank == 0:
        self.write_shm(method_name, *args)        # ① rank0 序列化命令到 SHM
    method = getattr(self, method_name)           # ② 各 rank 本地执行
    return method(*args)
```

子 rank 的 `loop()`：

```python
def loop(self):
    while True:
        method_name, args = self.read_shm()       # 阻塞 event.wait + 解析
        self.call(method_name, *args)
        if method_name == "exit": break
```

`read_shm` / `write_shm`：

```python
# write
data = pickle.dumps([method_name, *args])
n = len(data)
self.shm.buf[0:4]   = n.to_bytes(4, "little")
self.shm.buf[4:n+4] = data
for event in self.event: event.set()

# read
self.event.wait()
n = int.from_bytes(self.shm.buf[0:4], "little")
method_name, *args = pickle.loads(self.shm.buf[4:n+4])
self.event.clear()
```

特点 ✨：

- 🪟 **零拷贝控制面**：参数（Sequence 列表等）走 SHM + pickle，比 `mp.Queue` 更轻。
- 📞 **同步事件**：每个 worker 拥有独立 `mp.Event`，主进程一次性 `set` 多个，避免 broadcast 风暴。
- 🧷 **优雅清理**：启动时主动 `unlink` 旧的同名 SHM，崩溃重启不会泄漏。

## 💾 1.7.6 KV-Cache 与权重的分布式分配

### KV-Cache

每个 rank 独立分配 KV cache（按 `num_kv_heads / world_size` 切分）：

```python
num_kv_heads = hf_config.num_key_value_heads // self.world_size
self.kv_cache = torch.empty(2, num_layers, num_kvcache_blocks,
                            block_size, num_kv_heads, head_dim)
```

> ⚠️ 各 rank 的 `num_kvcache_blocks` 由本卡空闲显存独立估算，因此**严格要求各 rank 显存对称**（同型号、同负载），否则需要把 `num_kvcache_blocks` 取 min 后重新对齐（当前未做，使用者需保证同质化）。

### 权重加载

`load_model`（`KvChat/utils/loader.py`）解析 safetensors，调用 `param.weight_loader`，每个并行 Linear 自带 `weight_loader` 仅拿走自己 rank 的切片：

```python
# ColumnParallelLinear.weight_loader
shard_size = param_data.size(self.tp_dim)
start_idx  = self.tp_rank * shard_size
loaded_weight = loaded_weight.narrow(self.tp_dim, start_idx, shard_size)
param_data.copy_(loaded_weight)
```

`packed_modules_mapping`（`Qwen3ForCausalLM`）将 HF 权重名映射到合并后的 QKV / GateUp 参数，减少分散的 Linear 数量、提升通信粒度。

## 🧯 1.7.7 错误恢复

| 故障 | 处理 |
| --- | --- |
| 旧 SHM 残留 | `try/except FileNotFoundError` 主动 `unlink` |
| CUDA Graph 在 WSL 失败 | `_check_cuda_graph_support()` 捕获 RuntimeError → 退化 eager |
| Triton 预热失败 | `warmup_triton_cache` 仅打 warning，不中断流程 |
| 子进程异常退出 | `atexit` → `model_runner.call("exit")` → `dist.barrier` + `dist.destroy_process_group` |

## 📈 1.7.8 性能与扩展性

- 📦 **通信量**：每层一次 `all_reduce`（attention 输出）+ 一次 `all_reduce`（mlp 输出），符合标准 Megatron 风格。
- 🔢 **采样发生在 rank 0**：避免每个 rank 都做 multinomial，并配合 `ParallelLMHead.gather` 在 rank 0 拼接 logits。
- 🧠 **CUDA Graph 适配**：仅在单/多卡 decode 路径上使用；在 TP>1 模式下 NCCL op 也可被 graph 捕获（PyTorch 支持），首批捕获后的 step 几乎无 Python 开销。

---

## 🧾 1.7.9 一句话总结

> KvChat 的分布式体系采用 **"NCCL Tensor Parallel + 主从共享内存调度"** 的混合模型：每张 GPU 都跑同一个 Qwen3 的切片 forward，控制面通过 SHM/Event 由 Rank 0 集中下发，让"单卡 demo"和"8 卡推理"共享同一套 Scheduler / Block 管理代码。🛰️
