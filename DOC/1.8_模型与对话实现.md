## 🧬 1.8.1 模型整体结构

文件：`KvChat/models/qwen3.py`

```
Qwen3ForCausalLM
 └── Qwen3Model
      ├── VocabParallelEmbedding         # 词表分片 + all_reduce
      ├── ModuleList[Qwen3DecoderLayer × L]
      │     ├── input_layernorm   (RMSNorm)
      │     ├── Qwen3Attention
      │     │     ├── QKVParallelLinear
      │     │     ├── q_norm / k_norm    (无 qkv_bias 时启用)
      │     │     ├── rotary_emb         (RoPE)
      │     │     ├── Attention          ← Flash-Attn + Paged + 压缩
      │     │     └── RowParallelLinear  (o_proj)
      │     ├── post_attention_layernorm (RMSNorm)
      │     └── Qwen3MLP
      │           ├── MergedColumnParallelLinear (gate_up_proj)
      │           ├── SiluAndMul
      │           └── RowParallelLinear  (down_proj)
      └── RMSNorm (final norm)
 └── ParallelLMHead                       # 可与 embed_tokens 共享权重
```

### Qwen3DecoderLayer.forward

```python
def forward(positions, hidden_states, residual, Layer):
    if residual is None:
        hidden_states, residual = self.input_layernorm(hidden_states), hidden_states
    else:
        hidden_states, residual = self.input_layernorm(hidden_states, residual)
    hidden_states = self.self_attn(positions, hidden_states, Layer)
    hidden_states, residual = self.post_attention_layernorm(hidden_states, residual)
    hidden_states = self.mlp(hidden_states)
    return hidden_states, residual
```

🎯 设计点：

- 🪜 **Pre-Norm + 延迟残差**：`residual` 在层间一路携带，到下一层 `*_layernorm(x, residual)` 才完成"add 后 norm"，便于融合。
- 🔣 **Layer id 显式传递**：`Attention` 需要按层区分 KV cache 与 Query Window 写入位置。

### Qwen3ForCausalLM

```python
packed_modules_mapping = {
    "q_proj": ("qkv_proj", "q"),
    "k_proj": ("qkv_proj", "k"),
    "v_proj": ("qkv_proj", "v"),
    "gate_proj": ("gate_up_proj", 0),
    "up_proj":   ("gate_up_proj", 1),
}
```

- 🧷 让 `KvChat/utils/loader.py` 在加载 HF safetensors 时，自动把分散的 `q/k/v_proj`、`gate/up_proj` 塞入 KvChat 合并后的并行 Linear。
- 🔁 `tie_word_embeddings=True` 时直接 `lm_head.weight.data = embed_tokens.weight.data`，节省词表显存。

## 🌡️ 1.8.3 采样：`Sampler`

文件：`KvChat/layers/sampler.py`

```python
@torch.compile
def forward(self, logits, temperatures):
    logits = logits.float()
    logits = logits - logits.max(dim=-1, keepdim=True)[0]   # 数值稳定
    logits = torch.clamp(logits, -1e8, 1e8)
    temperatures = torch.clamp(temperatures, 1e-2, 100.0)
    logits = logits / temperatures.unsqueeze(1)
    probs  = torch.softmax(logits, dim=-1)
    probs  = torch.clamp(probs, 1e-10, 1 - 1e-10)
    if (prob_sum < 0.99).any() or (prob_sum > 1.01).any():
        probs = probs / prob_sum                           # 归一化保护
    try:
        return torch.multinomial(probs, num_samples=1).squeeze(-1)
    except RuntimeError:
        return torch.argmax(probs, dim=-1)                 # 兜底贪心
```

特性 ✨：

- 🛡️ **健壮性**：clamp logits、clamp temperature、clamp probs、归一化校验，五道护栏避免 NaN / inf。
- 🧯 **Fallback**：multinomial 抛错时退化为 argmax，保证生成不中断。
- ⚡ **`@torch.compile`**：Pytorch 图编译减小 Python 开销。

`SamplingParams` 强制 `temperature > 1e-10`（不允许 greedy=0），实际使用上由调用方设 `temperature=1.0` 走采样路径。

## 🧰 1.8.4 引擎入口：`LLM`

文件：`KvChat/llm.py`

```python
from KvChat.engine.llm_engine import LLMEngine
class LLM(LLMEngine): pass
```

- 仅是别名，方便 `from KvChat import LLM` 这种简洁导入。
- 真正逻辑全部在 `LLMEngine`（详见 1.6 / 1.7）：包含 `add_request / step / generate / get_session_stats / print_session_stats / exit`。

`LLMEngine.generate` 提供"批量同步推理"形式：传入多个 prompts + sampling_params，返回每个序列的 `{text, token_ids}`，并自动用 tqdm 显示 prefill / decode 的吞吐。

## 💬 1.8.5 多轮对话脚本：`chat.py`

完整脚本逻辑：

```python
model_path = os.path.expanduser("~/huggingface/Qwen3-4B")
tokenizer  = AutoTokenizer.from_pretrained(model_path)
llm = LLM(model_path, enforce_eager=False, tensor_parallel_size=1)

messages = []
compress_enabled = True

while True:
    user_input = input("\n> ").strip()
    if user_input == "/exit":   break
    if user_input == "/reset":  messages = []; continue
    if user_input == "/compress on":  compress_enabled = True;  continue
    if user_input == "/compress off": compress_enabled = False; continue

    messages.append({"role": "user", "content": user_input})
    prompt = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
    llm.model_runner.config.kv_compress_enabled = compress_enabled
    sampling_params = SamplingParams(temperature=1.0, max_tokens=32000)
    llm.add_request(prompt, sampling_params)

    print("Assistant: ", end="", flush=True)
    generated_token_ids = []
    while not llm.is_finished():
        outputs, num_tokens, step_token_ids, _, _ = llm.step()
        if step_token_ids is not None:
            for tid in step_token_ids:
                generated_token_ids.append(tid)
                print(tokenizer.decode([tid], skip_special_tokens=False), end="", flush=True)
    print()

    assistant_text = tokenizer.decode(generated_token_ids, skip_special_tokens=True)
    messages.append({"role": "assistant", "content": assistant_text})
```

### 命令一览 🎮

| 命令 | 作用 |
| --- | --- |
| `/exit` | 退出对话 |
| `/reset` | 清空 `messages`，开始新会话 |
| `/compress on` | 启用 KV 压缩（默认） |
| `/compress off` | 临时关闭 KV 压缩，便于对比生成质量与显存占用 |

### 流式输出工作流 🌊

`LLMEngine.step()` 在 decode 模式下会把"本步新生成的 token_ids"作为 `step_token_ids` 返回（见 1.6.7），`chat.py` 因此能逐 token 调用 `tokenizer.decode([tid])` 边推理边打印，体验类似真正的流式 API。

### KV 压缩热切换 🔥

```python
llm.model_runner.config.kv_compress_enabled = compress_enabled
self.model_runner.call("set_compress_enabled", ...)
```

`set_compress_enabled` 同步通知所有 rank（包括分布式的 worker 进程），并在每个 `Attention` 模块上更新 `kv_compress_enabled`。这意味着压缩开关**对当前请求即时生效**，无需重启引擎。

> ⚠️ 需要注意的是 Query Window 缓冲区只在引擎初始化时分配（`config.kv_compress_enabled=True` 时）。运行期切到 off→on 后仍可工作，只要初始化阶段已开启过。

## 🧠 1.8.6 一次完整对话的内部时序

```
用户输入 "你好，请介绍下自己"
   │
   ▼
tokenizer.apply_chat_template + encode               # CPU
   │
   ▼
LLM.add_request → Sequence(seq_id=k, prompt_ids)
   │
   ▼
LLMEngine.step()
   ├── Scheduler.schedule()     ──►  Prefill 批 (此条短，立刻入选)
   ├── ModelRunner.run(seqs, prefill=True)
   │     ├── prepare_prefill (slot_mapping / cu_seqlens / block_tables)
   │     ├── Qwen3Model forward
   │     │     └── 每层: store_kvcache → flash_attn_varlen_func
   │     ├── compute_logits (按 cu_seqlens_q 取最后一个隐藏向量)
   │     └── Sampler → token_id
   └── postprocess: append_token, 检查 EOS / max_tokens
   │
   ▼ 进入 Decode 循环
LLMEngine.step()  (反复 N 次, N=新生成 token 数)
   ├── Scheduler.schedule()  ──►  Decode 批
   ├── ModelRunner.run(seqs, prefill=False)
   │     ├── prepare_decode + prepare_compression_context
   │     ├── 每层 Attention:
   │     │     ├── store_kvcache (1 token)
   │     │     ├── if active: query_window_manager.append
   │     │     ├── if compress_any: MyCompressCompact + 触发 compression_events
   │     │     └── flash_attn_with_kvcache
   │     └── Sampler → token_id
   ├── postprocess:
   │     ├── 处理 compression_events → block_manager.truncate_blocks
   │     ├── append_token, EOS 检查
   │     └── 终止时 deallocate
   └── chat.py 解码并 print(token, end="", flush=True)  → 流式输出
```

整个过程对用户无感，仅暴露"逐 token 文字流"。

## 📦 1.8.7 子模块复用关系

| 上层 | 复用的下层 | 备注 |
| --- | --- | --- |
| `chat.py` | `LLM`, `SamplingParams`, `tokenizer` | 仅薄壳 UI |
| `LLMEngine` | `Scheduler`, `ModelRunner`, `Sequence`, `perf_monitor` | 控制面大脑 |
| `ModelRunner` | `Qwen3ForCausalLM`, `Sampler`, `QueryWindowManager`, `BlockManager`(间接) | 计算面执行器 |
| `Qwen3*` | `Attention`, `RMSNorm`, `RoPE`, 各 Parallel Linear | 模型骨架 |
| `Attention` | `flash_attn_varlen_func`, `flash_attn_with_kvcache`, `store_kvcache`, `MyCompressCompact` | 高性能算子 |

## 🧾 1.8.8 一句话总结

> KvChat 用一个**通用的 `Qwen3ForCausalLM` + 自带分页/压缩能力的 `Attention` 模块**承载模型本体；用一个**鲁棒采样的 `Sampler`**完成 token 选择；最后用 90 行的 `chat.py` 把"输入→Prefill→Decode→流式输出→历史拼接"全链路打通，对外提供熟悉的多轮对话体验。🎤
